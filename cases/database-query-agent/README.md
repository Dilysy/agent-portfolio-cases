# 自然语言数据库查询 Agent

## 1. 项目背景

业务人员常需要从数据库中查询订单、用户、收入或库存等信息，但不一定熟悉 SQL。该案例用于展示 Agent 如何把自然语言问题转换为可审查的只读 SQL。

## 2. 业务问题

Text-to-SQL 容易出现字段误用、口径不清和危险查询。第一版目标是面向本地样例数据库生成 SQL、解释结果并提供校验记录。

## 3. 解决方案

Agent 读取数据库 schema，理解用户问题，生成只读 SQL，执行查询并解释结果。所有 SQL 在执行前后都需要校验，避免写入、删除或更新操作。

## 4. Agent 设计

- Schema 理解节点：读取表、字段和字段说明。
- 问题解析节点：识别指标、维度、时间范围和过滤条件。
- SQL 生成节点：生成只读查询。
- 安全校验节点：拦截非 SELECT 操作和过大查询。
- 结果解释节点：将查询结果转成业务语言。

## 5. 工具调用

- 数据库连接：读取本地样例库。
- SQL 执行：执行只读查询。
- SQL 校验：检查危险语句和字段存在性。
- Markdown 输出：记录问题、SQL、结果和解释。

## 6. 实现流程

1. 准备本地样例数据库。
2. 读取 schema。
3. 输入自然语言问题。
4. 生成并校验 SQL。
5. 执行查询。
6. 输出结果解释和复核记录。

## 7. 输出结果

第一版输出自然语言问题、生成 SQL、查询结果摘要、解释和校验结论。当前不连接真实生产数据库。

## 8. 评估方式

- SQL 正确性：查询字段、过滤条件和聚合逻辑是否正确。
- 安全性：是否只执行只读语句。
- 结果一致性：解释是否忠于查询结果。
- 可复核性：是否记录 schema、SQL 和人工检查结论。

## 9. 可扩展方向

- 后续可扩展多轮追问。
- 后续可扩展指标语义层。
- 后续可扩展 SQL 单元测试和查询成本限制。
