# 自动化深度研究 Agent

## 1. 项目背景

本案例基于 `~/Documents/hello-agents/docs/chapter14/` 中的“自动化深度研究智能体”章节复现和改造整理。该章节不是当前作品集中的完整源码交付，而是一个教程级方案，描述了用 HelloAgents 构建深度研究助手的架构、流程和关键模块。

## 2. 业务问题

深度研究任务通常信息发散、来源分散、事实更新快，并且用户要求引用可追溯。传统搜索方式需要人工反复执行“搜索、阅读、总结、整理”，容易遗漏关键子问题。

## 3. 解决方案

采用 TODO 驱动研究范式，将开放研究主题拆成 3-5 个可执行子任务。系统逐个搜索、总结并记录来源，最后生成结构化 Markdown 报告。整个流程强调规划、执行、记录和整合，而不是一次性让模型生成长文。

## 4. Agent 设计

- `TODO Planner`：将研究主题拆成子任务，每个子任务包含标题、研究意图和搜索查询。
- `Task Summarizer`：读取搜索结果，提取关键事实、观点、数字、日期和引用来源。
- `Report Writer`：整合各子任务总结，生成最终研究报告。
- 协调器：负责创建研究状态、逐项执行 TODO、保存笔记并通过 SSE 推送进度。

## 5. 工具调用

- `SearchTool`：统一搜索接口，章节中提到可扩展 Tavily、DuckDuckGo、Perplexity、SearXNG 等后端。
- `NoteTool`：将每个子任务的标题、意图、查询、搜索结果和总结保存为 Markdown 笔记，便于恢复和审计。
- FastAPI SSE：通过 `/research/stream` 或类似接口流式返回研究进度。
- 前端：章节方案使用 Vue3 + TypeScript，展示全屏研究弹窗、进度条、任务状态和 Markdown 报告。

## 6. 实现流程

1. 用户输入研究主题。
2. 前端通过 SSE 请求后端研究接口。
3. 后端创建研究状态。
4. TODO Planner 生成 3-5 个子任务。
5. 对每个子任务调用 SearchTool。
6. Task Summarizer 总结搜索结果并保留来源。
7. NoteTool 持久化阶段结果。
8. Report Writer 生成最终 Markdown 报告。

## 7. 输出结果

预期输出包括任务列表、进度日志、每个子任务的总结、来源引用和最终研究报告。当前作品集尚未把 chapter14 方案完整迁移成本地可运行应用，因此不写成已经完成在线部署或客户交付。

## 8. 评估方式

章节中提出可评估规划质量，例如子任务数量是否适中、覆盖是否全面、查询是否具体。作品集后续还需要补充来源质量、引用完整性、重复来源去重、报告事实一致性等评估表。当前没有本仓库内自动化评估结果。
