# 自然语言数据库查询 Agent Schema 示例

本 Schema 为本地演示用的模拟销售业务数据库结构，不包含真实企业数据、真实客户信息或生产数据库连接信息。正式使用时需要替换为企业授权的只读数据库 Schema，并进行字段权限和敏感信息复核。

## 1. Schema 设计目标

该 Schema 用于演示自然语言数据库查询 Agent 的核心流程：

1. 理解用户的自然语言经营问题。
2. 获取可查询表结构和字段含义。
3. 生成只读 SQL。
4. 执行聚合查询。
5. 输出查询结果和业务解释。

## 2. 表结构

### orders

订单事实表，用于记录销售订单的时间、地区、客户类型、商品类别和经营指标。

| 字段名 | 类型 | 示例 | 说明 |
| --- | --- | --- | --- |
| `order_id` | VARCHAR(32) | `ORD-2025-0001` | 订单编号 |
| `order_date` | DATE | `2025-03-18` | 订单日期 |
| `region` | VARCHAR(20) | `华东` | 订单所属地区 |
| `customer_type` | VARCHAR(20) | `大型企业` | 客户类型 |
| `product_category` | VARCHAR(30) | `AI 应用` | 商品类别 |
| `product_name` | VARCHAR(80) | `智能客服套件` | 商品名称 |
| `sales_amount` | NUMBER(12,2) | `12800.00` | 销售额 |
| `order_count` | NUMBER(10) | `8` | 订单数 |
| `gross_margin` | NUMBER(5,2) | `0.38` | 毛利率，0.38 表示 38% |

### customers

客户维表，用于描述客户类型、区域和行业属性。

| 字段名 | 类型 | 示例 | 说明 |
| --- | --- | --- | --- |
| `customer_id` | VARCHAR(32) | `CUST-001` | 客户编号 |
| `customer_name` | VARCHAR(80) | `模拟客户 A` | 客户名称，仅为演示占位 |
| `customer_type` | VARCHAR(20) | `中小企业` | 客户类型 |
| `region` | VARCHAR(20) | `华南` | 客户所属地区 |
| `industry` | VARCHAR(40) | `软件服务` | 客户行业 |

### products

商品维表，用于描述商品名称、类别和标准价格。

| 字段名 | 类型 | 示例 | 说明 |
| --- | --- | --- | --- |
| `product_id` | VARCHAR(32) | `PROD-001` | 商品编号 |
| `product_name` | VARCHAR(80) | `流程自动化助手` | 商品名称 |
| `product_category` | VARCHAR(30) | `AI 应用` | 商品类别 |
| `price` | NUMBER(12,2) | `9800.00` | 标准价格 |

## 3. 业务口径说明

- `sales_amount` 表示订单销售额，用于销售规模统计。
- `order_count` 表示聚合订单数，用于计算订单规模和平均客单价。
- `gross_margin` 为毛利率，示例中使用 0 到 1 之间的小数。
- `region` 可以作为订单地区或客户地区，真实项目必须明确口径。
- 当前 Schema 未包含真实客户标识、真实合同、真实付款或发票信息。

## 4. 安全边界

企业落地时，应基于该 Schema 进一步加入：

1. 只读数据库账号。
2. 表级和字段级白名单。
3. 敏感字段脱敏规则。
4. SQL 行数限制和超时限制。
5. SQL 审计日志。
6. 执行前人工确认机制。
